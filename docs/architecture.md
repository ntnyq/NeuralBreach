# 架构与数据

## 代码组织

应用层保留在根目录的 `main` 包中，按职责拆文件，共享窗口状态通过包内方法协作：

| 文件                                  | 职责                                                           |
| ------------------------------------- | -------------------------------------------------------------- |
| `main.go`、`window.go`、`menu.go`     | 原生入口、窗口状态与生命周期、页面导航、后台任务调度和菜单命令 |
| `session.go`                          | 会话计时、开始、暂停、继续、选格、结算、教程和提示             |
| `generation.go`                       | 应用层生成编排、随机种子和题目去重预留                         |
| `persistence.go`                      | 异步保存、保存后退出、损坏存档修复和文件导出                   |
| `settings.go`                         | 设置草稿、应用设置、窗口缩放和音频同步                         |
| `view.go`、`theme.go`                 | 页面分发、公共布局与文案映射、主题、公共控件和视觉效果         |
| `view_menu.go`、`view_game.go`        | 主菜单与新局设置；对局、棋盘、暂停和结算页面                   |
| `view_records.go`、`view_settings.go` | 历史筛选、复盘状态与页面；设置页面                             |

`internal/` 保留现有包边界：`game/puzzle.go` 负责确定性生成，`game/solver.go` 负责有预算的提示搜索；`records/store.go` 负责存档，`records/stats.go` 和 `records/export.go` 分别负责统计与 CSV 编码。生成与搜索测试分别放在 `puzzle_test.go` 和 `solver_test.go`，跨页面和持久化流程仍由应用层集成测试覆盖。

`locales/`、`resources/`、`tools/` 和 `docs/` 继续分别承载翻译、嵌入资源、独立工具和文档，入口及构建命令保持不变。

## 游戏状态

`internal/game` 不依赖窗口、音频或磁盘。Session 保存实际棋盘、目标、逐步坐标与累计有效操作毫秒、模式、辅助次数、恢复次数和结局。合法输入依次检查超时、位置、已用格，再追加缓冲、匹配所有目标，最后检查全上传、容量和可移动性。

计分使用整数倍率分子（分母为 2），最后统一向下取整。时间和节约奖励只在全上传时发放，不限时练习没有时间奖励。完整公式和 2790 分验收示例见[规则](./game-design.md)。

`window.go` 定义主线程持有的页面、会话和设置草稿，并调度刷新。`session.go` 负责会话操作与计时，`settings.go` 负责设置应用。33ms 刷新只负责显示；计时通过单调时间差计算并保留不足毫秒的余量，前台卡顿仍扣时。进入暂停、设置或确认框之前结清有效时间。重新继续重设计时基点。

## 可解生成

版本 1 使用固定 SplitMix64。先生成不重复的合法路径，在路径上取相互重叠的序列，填充其余代码。最多四个目标，枚举目标排列可求出忽略棋盘时的最短公共超串长度；这个长度是任何棋盘解法的下界。生成器要求下界不低于难度最短步数，并提供在难度上界内的合法全上传路径，因此无需在生成阶段穷举棋盘即可证明可解和难度范围。

拒绝重复/包含目标。尝试 512 次后使用固定代码流和阶梯路径的可验证后备方案。每次返回前验证整个联合路径，不是仅验证各个目标。相同版本、种子和难度可重现同题。

随机标准局和未指定种子的练习另加本地去重：以规则版本、难度、按位置排列的棋盘及按显示顺序排列的目标序列计算 SHA-256 指纹，不包含种子或解法路径。重复则换随机种子，最多尝试 128 次，耗尽或写入失败时报告错误，不交付重复题。指定种子的练习和历史关卡练习跳过去重检查，原有版本 1 的种子映射保持不变；教程不加入指纹集合。

练习提示从当前路径进行深度搜索，利用剩余目标长度剪枝，最多访问 250000 个节点并支持取消。区分「确定无解」和「搜索预算耗尽」。新输入、撤销、离开游戏或关闭窗口取消旧任务，过期回调由 `internal/tasks` 拦截。

## 持久化

数据版本 1 包含 `version`、`revision`、`settings`、`active`、`history` 和可选的 `puzzleFingerprints` 集合。读取旧存档时从历史及非教程活动局补录指纹，标准、练习及放弃的关卡都纳入。成绩分项和已上传状态由不可变棋盘与步骤确定性重算，避免保存重复字段后互相矛盾。历史保存实际棋盘和一条完整解法，未来生成器变化不会改变旧复盘。

UI 捕获深拷贝快照，后台提交以互斥锁串行写入，并拒绝低于已提交 revision 的旧写入。每次提交经过结构、合法路径和结束原因校验，再写同目录临时文件、同步并原子替换。结算在一个快照里按局 ID 去重、加入历史并清空活动槽。退出等待最终提交成功；关闭后回调不再接触界面。

随机新局先在同一存储锁下检查并持久化指纹，再交给 UI 展示；指纹预留保留当前已提交快照的设置、活动局、历史及 revision。普通提交会合并存储端已预留的指纹，避免稍后完成的 UI 快照覆盖它们。任务在预留后取消时仍保留指纹，宁可跳过尚未展示的题也不遗忘已预留内容。指纹不随结算移除；保证范围是同一份本地数据，删除、回滚或重建数据会重置其去重范围。

标准、练习和教程共用活动槽。教程存档额外要求不限时、无提示/撤销且步骤是教学解法的前缀；恢复后仍受教学步骤约束。教程完成或放弃只清空活动槽，不加入历史，也不参与统计。

已有文件必须显式声明受支持的版本，`{}`、`null` 和缺少版本的对象不会被默认值补成有效存档。读取错误或未知版本会锁住写入。修复先原样备份，再重建；备份失败不会覆盖原文件。受保护数据的错误区统一提供备份重建与不保存退出，不提供必然失败的重试写入；普通写入失败仍可重试。使用文件系统错误测试验证失败保留原数据。原子替换提供文件一致性，但不承诺断电时目录元数据的硬件级持久性。

## 声音与视觉

`internal/sound` 使用 MyGo audio 的单个流解码器，所有声部共用 24kHz 采样时钟。原创建模包含低音、环境 drone、踢鼓、金属噪声和高频序列；状态改变通过约 250ms 的平滑增益调整声部。预加载短音效，页面切换不重复创建音乐播放器。默认总/音乐/音效音量为 80/65/85。

音频引擎接收自己的 `sound.Config`，由应用层 `settings.go` 从存档设置映射总音量、音乐音量、音效音量、静音和动态音乐开关。后台静音与设置预览由应用层选择播放状态，音频包不依赖存档包。

主菜单使用内嵌的生成背景 `resources/menu-background.png`；来源和完整提示词保存在 `resources/README.md`，按钮、标题和所有交互仍由原生元素绘制。

字体从 `resources/fonts` 嵌入注册，英文字形使用 Rajdhani 500/600。中文、日文、韩文由系统字体回退。动画只绘制边缘碎片，不改变格子位置、焦点和判定；减少动态效果覆盖其他视觉动态开关。

## 验证边界

规则测试覆盖首行/行列/复用、匹配后缀、序列重叠、最后一格优先、超时、练习撤销与评分。生成器检查四档各 250 个种子的确定性、联合解法和长度界限。存储测试覆盖并发乱序提交、去重、损坏保护、备份和写入失败。

MyGo headless 测试验证导航、教程、暂停遮挡、设置返回和五语言布局。原生音频设备、失焦、系统关闭和文件选择框需在目标平台实测；Windows/Linux 交叉编译不能代替这些检查。

持久化窗口测试执行真实后台写入，通过注入 UI 回调队列在测试线程交付结果，覆盖教程保存退出/重开续玩、完成后清槽，以及损坏存档下取消或确认不保存退出；测试数据全部位于临时目录。
